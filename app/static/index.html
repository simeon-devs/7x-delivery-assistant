Why a prompt injection cannot get past it

There is no reliable defence against talking a model into something. So the model was never given the decision.

It starts knowing nothing

No shipment data reaches the system prompt, so it cannot answer from context. To learn anything about a parcel it has to call a tool, and the tool decides what comes back.

It is never shown the rules

Nothing it sees says whether an action is permitted. It finds out by attempting, and the gate answers with a sentence for the customer and a case for the queue. It cannot reason around a rule it was never given.

One door, always logged

Every write goes through a single function that re-reads the record, checks the gate, writes, and records what happened either way. Refused to change the address on EX400001AE. This parcel has 389.18 AED to collect on delivery.

What is real here, and what is staged

Real

The assistant, both actions, the guardrails and the database writes. After a conversation, a row is genuinely different.

The cleaning layer and every number on this page. 866 in equals 8 test records plus 18 superseded duplicates plus 840 clean, reconciled on every run.

Staged

Shipment records are synthetic, supplied with the assignment.

The WhatsApp channel is simulated. It is not connected to the WhatsApp Business API, and no SMS is ever really sent. The verification step prints its own code on screen and says so.
